## User Story

**Epic:** EP-002 — Partecipanti e Inviti
**Priorità:** HIGH | **Story Points:** 5

**Story**
Come Marco (Coordinatore), voglio generare un link di invito al viaggio che posso copiare e condividere tramite qualsiasi canale (WhatsApp, email, ecc.), così che i miei amici possano unirsi senza che io debba gestire indirizzi email o aggiungere utenti manualmente.

**Criteri di Accettazione**
- [ ] Solo gli organizzatori possono generare il link dal tab partecipanti (`/trips/[id]/participants`)
- [ ] Il link è generato con token univoco e scade dopo 24 ore
- [ ] Il link è mostrato in pagina con un pulsante "Copia" per condividerlo via qualsiasi canale
- [ ] Se esiste già un link attivo (non scaduto), viene mostrato quello; l'organizzatore può rigenerarne uno nuovo
- [ ] Il tab partecipanti mostra i partecipanti attivi con badge ruolo e quelli disattivati separatamente

## Soluzione Tecnica

La storia introduce il modello `TripInvite` (token multi-uso con scadenza 24h) senza dipendenze email esterne — Resend non è coinvolto. Il link generato è condivisibile via qualsiasi canale; la consumazione del token (join al viaggio) è gestita da US-005.

- **Schema Prisma — `TripInvite`:** campi `id` (UUID), `tripId` (FK→Trip, cascade delete), `token` (unique), `expiresAt`, `createdAt`. Nessun campo email — il token identifica il link, non l'invitato. Aggiungere relazione inversa `invites TripInvite[]` su `Trip`. Eseguire `npx prisma db push && npx prisma generate`.
- **Server action `generateInviteLink(tripId)` in `src/app/actions/invites.ts`:** auth via Supabase + findUnique dbUser, verifica `TripParticipant` con `role: 'ORGANIZER'` per il trip, crea `TripInvite` con `token: crypto.randomUUID()` e `expiresAt: new Date(Date.now() + 86_400_000)`, restituisce `{ success: true, token, expiresAt }`. Non serve `revalidatePath` — la UI aggiorna il link lato client dopo la risposta dell'action.
- **Pagina `/trips/[id]/participants/page.tsx`:** Server Component — `getCurrentUser()` + redirect se non autenticato, verifica partecipazione al trip, fetch parallelo di `TripParticipant[]` (con user info) + ultimo `TripInvite` non scaduto (`findFirst({ where: { tripId, expiresAt: { gt: new Date() } }, orderBy: { createdAt: 'desc' } })`), render di `<ParticipantsTab>` con dati e `currentUserRole`.
- **`src/components/trips/participants-tab.tsx`:** Client Component — sezione link di invito (solo ORGANIZER): se link attivo mostra URL readonly + pulsante "Copia" (`navigator.clipboard.writeText`) con fallback input selezionabile + pulsante "Rigenera" che chiama l'action; se nessun link mostra pulsante "Genera link"; sezione partecipanti attivi con badge ruolo; sezione partecipanti disattivati (se presenti).
- **URL del link:** formato `${window.location.origin}/invite/${token}` — la route `/invite/[token]` sarà implementata da US-005.
- **Middleware:** nessuna modifica necessaria — la protezione di `/trips/:path*` è già delegata ai Server Component via `getCurrentUser() → redirect`, pattern identico a US-002 e US-003.

## Strategia di Test

La priorità è verificare il filtro di scadenza (silenzioso se sbagliato) e i guard di autorizzazione — i due rischi maggiori con il minor segnale di errore visibile.

- **Unit test `generateInviteLink` — autorizzazione:** utente non autenticato → errore; utente PARTICIPANT (non ORGANIZER) → errore; ORGANIZER → record creato con token non vuoto e `expiresAt` a circa 24h dal momento della chiamata.
- **Unit test `generateInviteLink` — link multipli:** due chiamate successive creano due record con token distinti; entrambi sono validi (il secondo non invalida il primo).
- **Integration test scadenza:** un `TripInvite` con `expiresAt` nel passato non viene restituito dalla query di fetch; uno con `expiresAt` nel futuro viene restituito correttamente.
- **Render test `ParticipantsTab`:** Testing Library — senza link attivo mostra pulsante "Genera"; con link attivo mostra URL + "Copia" + "Rigenera"; utente con ruolo PARTICIPANT non vede la sezione link; clic su "Copia" transiziona il pulsante a "Copiato!".
