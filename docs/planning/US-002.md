## User Story

**Epic:** EP-001 — Gestione Viaggi
**Priorità:** HIGH | **Story Points:** 2

**Story**
Come Marco o Sara, voglio vedere tutti i viaggi a cui partecipo da un'unica pagina, così da poter accedere rapidamente a qualsiasi viaggio in corso o programmato.

**Criteri di Accettazione**
- [ ] La pagina mostra tutti i viaggi in cui l'utente è organizzatore o partecipante
- [ ] Ogni voce in lista mostra nome viaggio, destinazione, date di inizio/fine e immagine di copertina (o placeholder)
- [ ] I viaggi sono ordinati per data di inizio, dal più vicino al più lontano
- [ ] Se l'utente non ha viaggi, viene mostrato un messaggio informativo con CTA per creare il primo viaggio
- [ ] Selezionando un viaggio si naviga alla dashboard del viaggio (`/trips/[id]`)

## Soluzione Tecnica

Approccio component-first che estende la pagina `/dashboard` esistente in una lista viaggi completa: si costruisce prima l'utilità di formattazione date e il `TripCard` riusabile, poi si refactora il dashboard per orchestrarli con la query Prisma e l'empty state.

- **`formatDateRange` in `src/lib/utils.ts`:** funzione `formatDateRange(start: Date, end: Date): string` che produce stringhe localizzate in italiano ("15–22 lug 2025", "28 dic – 3 gen 2026") via `Intl.DateTimeFormat` con `locale: 'it-IT'` — nessuna dipendenza esterna, riusabile in tutta l'app.
- **`src/components/trips/trip-card.tsx`** — Client Component con `Link` wrapper a `/trips/[id]`. Mostra: cover gradient/placeholder (mappa da `coverKey` nullable a un colore/gradient distinto), nome viaggio in font display, destinazione con icona pin, date range formattato, badge ruolo (ORGANIZER → "Organizzatore", PARTICIPANT → "Partecipante"), badge status calcolato dalle date (Prossimo / In corso / Passato).
- **`src/app/dashboard/page.tsx` — refactoring completo:** Server Component che esegue `prisma.tripParticipant.findMany({ where: { userId, status: "ACTIVE" }, include: { trip: true }, orderBy: { trip: { startDate: "asc" } } })`. Renderizza header con titolo "I miei viaggi" + pulsante "Nuovo viaggio" (`CreateTripModal` da US-001), tab di filtro per status (Tutti / In corso / Prossimi / Passati), griglia responsive TripCard (2 colonne desktop, 1 mobile). Nessun bottone aggiuntivo "Filtri" — le tab sono l'unico meccanismo di filtraggio. Empty state (quando nessun TripParticipant ACTIVE): header senza bottone "Nuovo viaggio", sola CTA nell'empty state ("Crea il tuo primo viaggio"). I viaggi passati sono mostrati con cover in scala di grigi (`filter: grayscale(1)`).
- **Stub `src/app/trips/[id]/page.tsx`:** placeholder minimo per evitare 404 quando si clicca una TripCard. La pagina completa è oggetto di US-003. Aggiungere `/trips/:path*` alla lista dei percorsi protetti in `src/middleware.ts`.
- **Dipendenza su US-001:** `CreateTripModal` (US-001 TASK-05) deve essere disponibile. Questa storia assume US-001 completata.

## Strategia di Test

La strategia prioritizza il comportamento dell'ordinamento e del filtro sullo stato del partecipante — i due aspetti più rischiosi dal punto di vista della correttezza.

- **Unit test `formatDateRange`:** Vitest — same-month range, cross-month, cross-year, single-day. Verifica che l'output sia nella locale italiana attesa.
- **Render test `TripCard`:** Testing Library — rendering con/senza `coverKey`, role ORGANIZER vs PARTICIPANT, badge status per trip futuro/in corso/passato.
- **Integration test `/dashboard`:** query con 3 viaggi in ordini di startDate non crescente → verifica ordine in output; partecipante con `status: DEACTIVATED` → viaggio non appare; lista vuota → empty state visibile.
- **E2E navigazione:** click su TripCard → URL cambia in `/trips/[id]`; utente non autenticato → redirect a `/auth/signin`.
